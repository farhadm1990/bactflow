How BactFlow runs

Work left to right: QC the reads, assemble, then interpret the genomes. Only one pipeline can run at a time. Memory is a hard cap — keep it below what the machine actually has.

Start

Home

The home screen launches QC, Assembly, or Post-assembly. The top bar stays available on every page so you can switch views without stopping a run. Wiki is this page. While a process is live, Start / Filter / Install on the other modules stay inactive.

Resources — every module

CPUs and Memory

  • CPUs — threads for Nextflow, seqkit, Flye, SPAdes, Bakta, and similar tools.
  • Memory (GB) — hard cap for the run. Nextflow cannot schedule more than this; SPAdes is passed -m; the Nextflow JVM heap is limited. If you type more RAM than the host has, BactFlow lowers it automatically and leaves 1 GB for the system.
  • Small laptops: 4–8 GB and a modest CPU count. Assembly and CheckM are the hungry steps.
QC

Launch QC

Point at a FASTQ folder, choose the output directory, then:

  • Read type — Illumina, ONT, or PacBio. PacBio can hint HiFi vs CLR.
  • Concat reads — pool barcode folders into one FASTQ per sample when the sequencer split them.
  • Install BactFlow — first-time conda/Nextflow setup only. Uses the same run lock as pipelines.
  • Initiate read cat — list (and pool) files.
  • Filter reads — length/quality gates. Illumina uses paired R1/R2 filters.
  • Display read statistics / Visualize reads — seqkit stats and quality plots. They also take the lock while they run.
Assembly

Launch Assembly

  • Only install and exit — prepare the environment, do not assemble.
  • FASTQ directory — long reads for Flye / Unicycler / PacBio, or Illumina pairs for SPAdes (sample_R1 / sample_R2).
  • Assembler — Flye (ONT), SPAdes (Illumina isolate), Unicycler (hybrid; also needs a short-read directory), PacBio Flye.
  • ONT / PacBio read type — raw, corrected, or HiFi. Wrong mode wastes RAM and time.
  • Filter / coverage / genome size — optional downsampling before Flye.
  • Medaka polish — extra RAM; keep Memory high enough or leave it off on small machines.
  • Resume — continue a previous Nextflow run in the same output directory.
  • Clean up work dir — after a successful run, delete out_dir/.nextflow-work and other temp files to free disk. Leave False if you plan to Resume later.
  • Start BactFlow. Stop cancels the tree. Display results appears when reports exist.
Post-assembly

Launch Post-assembly

  • Genome directory — folder of FASTA files (for example circulated assemblies). Required unless you only install.
  • Genome extension — usually fasta.
  • QUAST — assembly metrics. On by default.
  • Circulate — try to close circular chromosomes.
  • CheckM — completeness/contamination. Needs a CheckM database path. Heavy RAM.
  • GTDB-Tk — taxonomy. Needs the GTDB data path. Very heavy; raise Memory or skip on small hosts.
  • Bakta — annotation. Needs a Bakta database. Linear plots, AMR (antibiotic only), orphans, and the gene heatmap read these results.
  • geNomad plasmids — optional plasmid/virus screen with a geNomad database.
  • MLST — PubMLST sequence typing (Torsten Seemann mlst). No extra database path. Shows ST table, ST bar chart, and allele heatmap.
  • Clean up work dir — after a successful run, delete out_dir/.nextflow-work and other temp files. Leave False if you plan to Resume later.
  • Generate report — after results exist, builds a narrative HTML + PDF from QUAST, CheckM, GTDB-Tk, MLST, Bakta/AMR, and geNomad into out_dir/bactflow_report/.
Results

After a run

When the pipeline finishes, the terminal hides and results open if something was produced. During a run you can still Display results without hiding the log. Theme switches light/dark. Genome visualization (linear plot, orphans, AMR highlight, heatmap) lives only in Post-assembly. Use Generate report for a single downloadable summary of every table that ran.

Lock

One process at a time

Navigation is always allowed. Launch buttons on other modules stay inactive until the current QC, Assembly, or Post-assembly job exits or you press Stop. That keeps two Nextflow runs from fighting over the same RAM.
